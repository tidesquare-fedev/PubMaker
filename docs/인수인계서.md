## 0. 30초 요약

- 반복적인 프로모션 페이지 퍼블리싱을 자동화하는 **브라우저 단독 실행 도구**다. 서버·DB·API 가 없다.
- 사용자가 이미지 URL을 넣고 이미지 위에 마우스로 영역을 드래그하면, 그 영역이 링크·쿠폰·앵커·영상으로 바뀐 **HTML 코드 문자열**을 만들어 준다.
- 코드는 전부 문자열 조합이다. 프레임워크 없음. React·Vue 없음. `js/*.js` 는 **번들되지 않는 전역 스크립트**다.
- 생성기 탭이 3개다: **투어비스(항공일반) · 베네피아/휴가샵 · SKT**. 셋은 UI가 비슷하지만 코드는 상당 부분 독립돼 있다.
- **가장 먼저 알아야 할 것**: `feature/tab-and-video` 브랜치가 `main` 보다 훨씬 앞서 있으며 **아직 머지되지 않았다**. 아래 [8. 인수 시점의 미해결 항목](#8-인수-시점의-미해결-항목) 참고.

## 2. 아키텍처 — 왜 이런 구조인가

### 2-1. 번들하지 않는다

`js/*.js` 는 ES module이 **아니다**. 전역 스코프를 공유하는 일반 스크립트이고, `index.html` 에서 `defer` 로 순서대로 로드된다.

```html
<script src="js/common.js" defer></script>
<script src="js/features.js" defer></script>
<script src="js/tourism.js" defer></script>
<script src="js/benefia.js" defer></script>
<script src="js/skt.js" defer></script>
```

**로드 순서가 곧 의존성이다.** `common → features → tourism → benefia → skt`.
`features.js` 는 `window.PubFeatures` 하나만 노출하고, 생성기 3종이 이를 참조한다.

> `features.js` 마지막 줄에 `if (typeof window !== "undefined") window.PubFeatures = PubFeatures;` 가 있는 이유:
> 최상위 `const` 는 전역 객체의 속성이 되지 않아 환경에 따라 참조가 끊긴다. 지우지 말 것.

Vite 는 개발 서버(HMR)와 정적 배포용으로만 쓴다. 번들링을 하지 않으므로 `vite.config.js` 의 **`copy-plain-scripts` 플러그인**이 빌드 시 `js/` 를 `dist/js/` 로 통째로 복사한다. 이 덕분에 `npm run dev` 결과와 `npm run build` 결과가 동일하다.

`build.minify: false` 로 둔 것도 의도적이다. 생성기 특성상 출력 코드 확인·디버깅이 잦다.

### 2-2. 외부 의존성

런타임 의존성은 CDN 2개뿐이다 (`index.html` 상단).

| 대상                          | 용도                                                     |
| ----------------------------- | -------------------------------------------------------- |
| `https://cdn.tailwindcss.com` | 생성기 **UI 화면**의 스타일. 생성되는 결과 코드와는 무관 |
| Pretendard (jsDelivr)         | 폰트                                                     |

npm 의존성은 전부 devDependencies (`vite`, `prettier`, `jsdom`) 이며 **런타임 라이브러리는 0개**다.

> Tailwind CDN 은 생성기 화면 전용이다. **생성되는 프로모션 코드에는 Tailwind 클래스를 절대 넣지 말 것.** 게시 페이지에는 Tailwind가 없다. 결과 코드는 전부 인라인 스타일 또는 `<style>` 블록이어야 한다.

## 4. 코드 생성 파이프라인

투어비스 기준 흐름 (`js/tourism.js`). 베네피아·SKT도 이름만 다르고 골격은 같다.

```
[사용자 입력]
  이미지 URL 행 추가 → 이미지 위 드래그로 영역 지정 → 영역 종류·링크·옵션 입력
      │
      ▼
buildOverlayTag(configRow, btn, platform, hasSidePadding)      tourism.js:908
  영역 1개 → <a> / iframe / video 등 오버레이 태그 문자열
      │
      ▼
buildImageBlocks(platform, skipMissingCoords)                  tourism.js:984
  이미지 1장 = <div position:relative> + <img> + 오버레이들  → 블록 배열
      │
      ▼
buildFullHtml(platform, skipMissingCoords)                     tourism.js:1027
  블록 배열을 감싼다:
    · 탭 콘텐츠 전환 ON  → PubFeatures.wrapBlocksWithTabSwitch  (우선)
    · 스티키 탭 ON       → PubFeatures.wrapBlocksWithStickyTabs
  headExtras / tailExtras 에 style·script 를 모아 최종 문자열 완성
      │
      ├─▶ generateCode()   tourism.js:1106  → textarea 에 코드 출력
      └─▶ renderPreview()  tourism.js:1140  → paintPreview() 로 iframe 에 주입
```

핵심 규칙 두 가지:

1. **탭 콘텐츠 전환과 스티키 탭이 동시에 켜지면 콘텐츠 전환이 우선**이고, 스티키 탭바는 출력되지 않는다 (`dom.test.mjs` 에 검증 케이스 있음).
2. **미리보기와 출력 코드는 같은 `buildFullHtml` 을 쓴다.** 미리보기만 고치는 식의 분기를 만들면 곧바로 어긋난다.

### 세 생성기의 구조 차이 (주의)

|              | 초기화 방식                                                   | 스코프                       |
| ------------ | ------------------------------------------------------------- | ---------------------------- |
| `tourism.js` | 파일 최상위에서 바로 실행                                     | 최상위 `const`/`let` 이 전역 |
| `benefia.js` | `initializeBenefiaTab()` 함수로 전체를 감싸고 L1196 에서 호출 | 함수 스코프                  |
| `skt.js`     | `initializeSktTab()` 함수로 전체를 감싸고 L1212 에서 호출     | 함수 스코프                  |

`tourism.js` 는 전역을 쓰기 때문에 **거기서 만든 변수명이 `benefia`/`skt` 와 충돌할 수 있다.** 새 전역 변수를 추가할 때는 `tourism` 접두사를 붙이는 기존 관행(`tourismSticky`, `tourismTabSwitch`)을 따를 것.

베네피아·SKT 의 중복 로직 통합은 의도적으로 보류된 상태다 ([9. 백로그](#9-백로그--후속-과제) 참고). **신규 공통 기능만 `PubFeatures` 로 뽑아 쓰는 것이 현재 합의된 방침이다.**

## 5. 테스트

```bash
npm test    # features.test.mjs → dom.test.mjs 순차 실행
```

의존성 없는 자체 하네스(`test/_harness.mjs`)를 쓴다. Jest·Vitest 없음. `check(name, condition, detail)` 로 단언하고 실패 시 `process.exitCode = 1`.

### `features.test.mjs` (43건)

`js/features.js` 를 **파일로 읽어 `new Function` 으로 평가**해 `PubFeatures` 를 꺼낸다 (모듈이 아니라 import 불가). 순수 함수만 검증 — `parseYoutubeId`, `swapOnOff`, `toPctRect` 등.

### `dom.test.mjs` (156건)

jsdom 에 `index.html` 을 올리고 `js/*.js` 를 순서대로 주입해 **실제 UI 배선**을 검증한다. 버튼 클릭 → 코드 생성까지 태워 보고 출력 문자열을 문자열 매칭으로 확인한다.

jsdom 이 레이아웃을 계산하지 않으므로 다음을 흉내 낸다 (`dom.test.mjs` 상단).

- `window.ResizeObserver` 스텁
- `HTMLElement.prototype.getBoundingClientRect` 를 600×2000 고정값으로 덮어씀
- `window.alert` 를 가로채 `errors` 배열에 수집 → 마지막 "런타임 오류" 섹션에서 **전 과정 무예외**를 단언

> 좌표 관련 기능을 만들면 이 FAKE 크기(600×2000)를 전제로 기대값을 계산해야 한다.

### 기능 수정 시 최소 절차

1. `npm test` 로 기존 199건이 통과하는지 먼저 확인
2. 코드 수정
3. 새 동작에 대한 케이스를 `features.test.mjs`(순수 로직) 또는 `dom.test.mjs`(UI 배선)에 추가
4. `npm test` 재실행 + `npm run dev` 로 실제 브라우저에서 눈으로 확인
5. [docs/사용설명서.md](사용설명서.md) 의 해당 절과 **8장 기능점검 체크리스트** 갱신
6. `npm run format` 후 커밋

> 5번을 빠뜨리면 문서와 동작이 어긋난다. 지금까지의 커밋은 대부분 코드와 문서를 **함께** 수정하고 있다. 이 관행을 유지할 것.

### `test/*.html` 의 정체

`test1.html` `test3.html` `test4.html` `test5.html` `ff_test.html` 은 **자동 테스트가 참조하지 않는다.** 개발 중 생성 결과를 브라우저에 직접 띄워 보려고 손으로 저장해 둔 스캐치 픽스처다. 참고 자료로 두되, 이것들이 깨졌다고 기능이 깨진 것은 아니다.

## 8. 인수 시점의 미해결 항목

### (1) `feature/tab-and-video` → `main` 머지 — 최우선

가장 중요한 인계 사항이다. 현재 배포된 프로덕션(`main` 기준)에는 **탭 스크롤 · 스티키 탭 · 탭 콘텐츠 전환 · 영상 첨부 · 앱 알림 설정이 반영돼 있지 않다.**

머지 전 확인:

- `npm test` 199건 전체 통과 (인계 시점 기준 통과 확인됨)
- `npm run build && npm run preview` 로 빌드 결과가 dev 와 동일한지 확인 — 특히 `dist/js/` 에 5개 파일이 모두 복사됐는지
- [docs/사용설명서.md](사용설명서.md) 8장 **기능점검 체크리스트**를 실제 브라우저에서 한 바퀴 돌 것. 좌표·스크롤 동작은 jsdom 이 잡지 못한다

### (2) 사용자 가이드 PDF 미완성

[docs/사용가이드-원고.md](사용가이드-원고.md) 는 텍스트가 완성돼 있으나 **스크린샷이 비어 있다.** 자리 표시자만 들어가 있고, 찍어야 할 12장의 목록·촬영 방법은 [docs/스크린샷-촬영목록.md](스크린샷-촬영목록.md) 에 정리돼 있다. 촬영 → 원고 삽입 → PDF 내보내기가 남은 작업이다.

### (3) 앱 알림 설정의 프런트 의존

`appAlarmSetting(설치URL)` 은 **생성기가 구현하지 않는다.** 앱 판별·딥링크·미설치 시 이동은 프런트가 게시 페이지에 구현하기로 한 약속이고, 생성기는 `href` 에 호출만 넣는다 (항공권 예약의 `promoFixPop` / `compactPopOpen` 과 동일한 방식). 게시 페이지에 함수가 없으면 버튼이 무반응이다. **프런트 담당자와 함수 존재 여부를 확인하는 절차가 운영상 필요하다.**

동일한 성격으로 `couponDownloadAll` 도 생성기가 만들지 않는다. 게시 페이지에 있어야 한다.

## 10. 함정 모음 (반드시 읽을 것)

1. **스크립트 로드 순서를 바꾸지 말 것.** `common → features → tourism → benefia → skt`. `js/*.js` 는 번들되지 않으므로 순서가 곧 의존성이다.
2. **`js/` 에 파일을 추가하면 `index.html` 에 `<script>` 태그를 직접 추가해야 한다.** 자동 감지가 없다. 빌드 복사는 `vite.config.js` 의 `copy-plain-scripts` 가 디렉터리 통째로 처리하므로 별도 등록은 불필요하다.
3. **`js/*.js` 에서 `import`/`export` 를 쓰면 즉시 깨진다.** 모듈이 아니다. `features.test.mjs` 가 `new Function` 으로 소스를 평가하는 것도 이 때문이다.
4. **생성되는 결과 코드에 Tailwind 클래스를 넣지 말 것.** 게시 페이지에는 Tailwind가 없다. 인라인 스타일 또는 `<style>` 블록만 쓴다.
5. **`swapOnOff` 는 파일명 끝의 `_on`/`_off` 만 치환한다.** 경로 중간의 `_` 를 건드리지 않도록 정교하게 짜여 있고 테스트도 있다. 정규식을 단순화하지 말 것.
6. **스티키 탭은 입력이 `_off` 하나지만 서버에는 `_on`/`_off` 두 파일이 모두 있어야 한다.** 사용자 문의 1순위다.
7. **좌표는 `%` 로 나간다.** `pct()` 가 `NaN`/`Infinity` 를 `"0.00"` 으로 막고 있다. 이미지가 로드되기 전에 원본 크기(`naturalWidth/Height`)를 읽으면 0이 된다 — 그래서 "이미지가 아직 로드되지 않았습니다" 가드가 존재한다.
8. **미리보기와 출력 코드는 같은 `buildFullHtml` 을 공유한다.** 한쪽만 고치는 분기를 만들지 말 것.
9. **탭 콘텐츠 전환 ON 이면 스티키 탭바는 출력되지 않는다.** 의도된 우선순위다.
10. **`.claude/` 는 `.gitignore` 에 들어 있다.** 로컬 에이전트 설정이며 저장소에 올라가지 않는다.
11. `.prettierrc` 는 `endOfLine: "auto"` 만 설정돼 있다 (Windows 개발 환경 대응). 커밋 전 `npm run format` 을 습관화할 것.
12. `common.js` 의 클립보드 복사는 **CRLF 로 변환해서** 넣는다. 붙여넣는 쪽이 CRLF 를 기대해서 그렇다. LF 로 바꾸지 말 것.

## 11. 자주 하는 작업 레시피

### 생성기 3종 모두에 새 공통 기능 추가

1. `js/features.js` 의 적절한 구획에 빌더 함수 작성 (`build***Style` / `build***Bar` / `build***Script` / `wrapBlocksWith***` / `render***Panel` 패턴을 따른다)
2. 파일 끝 `return { ... }` 에 함수 이름 추가 — **여기 빠뜨리면 다른 파일에서 안 보인다**
3. `index.html` 에 입력 UI 추가 (탭별로 `tourism-` / `benefia-` / `skt-` 접두사 id 규칙을 지킬 것)
4. 각 생성기의 `buildFullHtml` / `generate***Code` 에서 `headExtras` / `tailExtras` 에 결과를 밀어 넣는다
5. `features.test.mjs` 에 순수 로직 케이스, `dom.test.mjs` 에 배선 케이스 추가
6. 사용설명서 + 사용가이드 원고 갱신

### 특정 생성기 탭에만 기능 추가

해당 `js/{tourism,benefia,skt}.js` 안에서 처리한다. `tourism.js` 는 전역 스코프이므로 새 변수에 `tourism` 접두사를 붙일 것.

### 새 생성기 탭(4번째 브랜드) 추가

1. `index.html` 상단 탭 버튼에 `data-tab="새이름"` 추가 + `<div id="새이름-tab" class="tab-content hidden">` 본문 추가
2. `js/새이름.js` 를 만들되 `benefia.js` / `skt.js` 처럼 **`initialize새이름Tab()` 함수로 전체를 감싸는 방식**을 따를 것 (전역 오염 방지). `tourism.js` 방식은 따라 하지 말 것
3. `index.html` 마지막에 `<script src="js/새이름.js" defer></script>` 추가 (순서: features 이후)
4. `common.js` 의 `setupTabSwitching()` 은 `data-tab` / `id="{name}-tab"` 규칙만 지키면 자동 동작한다
5. `dom.test.mjs` 에 해당 탭 케이스 추가
